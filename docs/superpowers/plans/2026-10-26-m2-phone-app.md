# M2 Phone App (`web/play`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A phone controller web app that joins a room, shows the lobby, renders every `ControllerView` widget, survives reconnects, and a browser dev page that hosts a room and shows N phones, so REDLINE can be played end to end in a browser before the Godot TV app exists.

**Architecture:** Vite + TypeScript + Preact single-page app in `web/play`. A small `Session` state machine owns the SignalR connection, rejoin and storage; Preact components render its state. Widgets are pure components (`view` + `send` props). The ASP.NET Core server serves the built app; in development it serves `web/play/dist` directly.

**Tech Stack:** Vite 6, TypeScript 5 (strict), Preact 10, `@microsoft/signalr` 9+, `@fontsource/titillium-web`, Vitest + `@testing-library/preact` + happy-dom, Playwright (pre-installed Chromium) for the end-to-end smoke.

**Spec:** `docs/superpowers/specs/2026-10-18-arcbox-platform-design.md` §5 and §6.1; REDLINE phone copy in `docs/superpowers/specs/2026-10-25-redline-design.md` §3.3. Visual reference: `docs/superpowers/mockups/trivia-racer/broadcast.css` (`.phone`, `.pstatus`, `.pq`, `.tbtn`, `.ptimer`) and `14-driver-select.png`.

## Global Constraints

- Hub at `/hub`; JSON protocol; camelCase property names; enums as strings; `ControllerView` discriminator property is `kind` with values `wait`, `textEntry`, `choice`, `buttons`, `draw`.
- Hub methods (phone): `Join(code, name) → {code, playerId, secret}`, `Rejoin(code, playerId, secret)`, `SelectGame(gameId)`, `StartGame()`, `SendInput(viewId, payload)`. Host: `CreateRoom() → {code, hostToken}`, `ResumeHost(code, hostToken)`, `SelectGame`, `StartGame`, `ReturnToLobby`, `Kick(playerId)`.
- Server→client: `LobbyChanged(lobby)`, `ControllerView(view)`, `HostView(gameId, view)`, `GameEnded(results)`, `RoomClosed(reason)`, `Kicked`.
- Input payloads: buttons `{pressed: id}`, choice `{selected: [ids]}`, text `{text}`, draw `{strokes: [{color, width, points}]}` with points normalised 0..1.
- Storage key `arcbox:<CODE>` holds `{playerId, secret, name}`; the dev page namespaces it as `arcbox:<CODE>:<slot>` via `?slot=n` (iframes share localStorage).
- Names 1–12 characters, trimmed. Room codes are 4 letters, upper-cased client side.
- Reconnect backoff `[0, 1, 2, 5, 10, 10, 10, …]` seconds; stateful reconnect on; on `visibilitychange`→visible or `pageshow`, if not `Connected`, restart and `Rejoin`.
- Wake Lock requested while an input widget (anything but `wait`) is shown, released on `wait`; failures are ignored (needs HTTPS).
- 16px minimum input font (no iOS zoom), `viewport-fit=cover`, portrait, tap targets ≥ 48px.
- All names and server strings rendered as text (Preact default), never `dangerouslySetInnerHTML`.
- No external network at runtime: fonts come from `@fontsource`, not Google Fonts.

## Review Focus

1. **Clock skew on deadlines** — `deadlineUtc` is server time; a phone whose clock is off shows a wrong countdown. Expected: the countdown is cosmetic and clamps to `[0, 60]` s; input is never blocked client-side by it. Test in Task 3 (`Countdown clamps a deadline far in the future/past`).
2. **Double tap / input in flight when the view changes** — expected: a widget sends at most once per `viewId` and locks immediately; a new `viewId` re-enables it. Test in Task 3 (`Buttons sends once per viewId`).
3. **Stored secret for a room that no longer exists** — expected: `Rejoin` fails with "Room not found.", the stored entry is deleted and the Join screen shows with the code pre-filled. Test in Task 2.
4. **Join rejected mid-game or duplicate name** — expected: the exact server message is shown under the form, form stays filled. Test in Task 4.
5. **`RoomClosed` / `Kicked`** — expected: storage entry removed, a full-screen message with a "Join another room" button. Test in Task 2.

### Task 2: `Session` — connection, join/rejoin, storage, reconnect

**Files:**
- Create: `web/play/src/session/{session.ts, storage.ts, backoff.ts}`, `web/play/test/session.test.ts`

**Interfaces:**
- Consumes: `protocol.ts`.
- Produces:
  - `type SessionState = {screen: "join", code?: string, error?: string} | {screen: "connecting"} | {screen: "lobby", lobby: LobbyState, me: PlayerId} | {screen: "game", view: ControllerView, lobby: LobbyState, me} | {screen: "results", results: GameResults, lobby, me} | {screen: "closed", reason: string}`. (`results` is shown when `GameEnded` arrives and stays until the next `LobbyChanged` with `inGame` or the user dismisses it.)
  - `class Session { constructor(transport: Transport, store: KeyValueStore, slot?: string); state: SessionState; subscribe(fn): () => void; join(code, name): Promise<void>; resume(code): Promise<boolean>; send(viewId, payload): Promise<void>; selectGame(id); startGame(); onVisible(): Promise<void>; }`
  - `interface Transport { start(); stop(); invoke<T>(method, ...args): Promise<T>; on(method, handler); onReconnected(fn); onClose(fn); readonly connected: boolean }` with `signalrTransport(url)` built on `HubConnectionBuilder().withUrl(url).withAutomaticReconnect(backoffPolicy).withStatefulReconnect().build()`.
  - `backoffDelays(attempt: number): number` (ms) per the constraint list; never returns null (keep retrying every 10 s).
  - `storage.ts`: `storageKey(code, slot?)`, `loadSeat`, `saveSeat`, `clearSeat` over a `KeyValueStore` (`localStorage` in the app, a Map in tests).
- Behaviour: on `onReconnected` and on `onVisible` when not connected → `start()` then `Rejoin`. A `HubError` with message `Room not found.` on rejoin clears the seat and shows `join` with the code. `RoomClosed(reason)` or `Kicked` clears the seat and shows `closed`.

- [ ] **Step 1:** Tests with a fake `Transport` (records invokes, lets the test fire server messages): `join stores seat and shows lobby on LobbyChanged`; `ControllerView switches to game screen`; `GameEnded shows results until next game starts`; `resume with stored seat calls Rejoin`; `resume for a dead room clears seat and returns to join with code` (Review Focus 3); `reconnected triggers Rejoin`; `RoomClosed clears seat and shows closed` and `Kicked …` (Review Focus 5); `backoffDelays` yields 0,1000,2000,5000,10000,10000.
- [ ] **Step 2:** Run `npm test`; expect failures. **Step 3:** Implement. **Step 4:** `npm test` green.
- [ ] **Step 5:** Commit `feat(web): session state machine with rejoin and reconnect`.

### Task 3: Widgets, countdown, Wake Lock

**Files:**
- Create: `web/play/src/widgets/{Wait.tsx, Buttons.tsx, Choice.tsx, TextEntry.tsx, Draw.tsx, Countdown.tsx, ControllerScreen.tsx, wakeLock.ts}`, `web/play/test/widgets.test.tsx`

**Interfaces:**
- Each widget: `(props: {view: XView, send: (payload: object) => void}) => JSX`. `ControllerScreen({view, send, me})` picks the widget by `kind`, shows `header` in the status bar and the `Countdown` when `deadlineUtc` is set.
- `remainingSeconds(deadlineUtc: string, now: number): number` = `clamp(ceil((deadline − now)/1000), 0, 60)`.
- Send-once rule (Review Focus 2): every input widget keeps `sentFor: string | null`; after sending it disables itself until `view.viewId` changes. Choice with `allowMultiple` toggles selections and sends on a "Lock in" button, capped at `maxSelections`; single choice sends on tap. TextEntry enforces `maxLength`, trims, refuses empty. Draw: pointer-events canvas, strokes normalised to 0..1, colour palette from `colors` (default `#111`), Undo and Submit.
- Option rendering: label on the first line, `hint` as a dim second line when present.
- `wakeLock.ts`: `syncWakeLock(active: boolean)` — request on true when `navigator.wakeLock` exists, release on false, swallow errors.
