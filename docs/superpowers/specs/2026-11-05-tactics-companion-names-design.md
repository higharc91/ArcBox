# Subclass companion names

Issue #95. USER DECISION: all three subclass companions can be named, confirmed by the owner's issue comment. USER DECISION defaults from the issue: name on choosing a subclass, rename outside battle, leave unnamed companions unchanged, 1–16 Unicode letters with spaces/apostrophes/hyphens, only the owner, eight suggestions per kind. Empty input clears a saved name. Controls are rejected before whitespace normalization.

A character's optional name is omitted from old saves. Named sheets carry the chosen subclass's companion monster ID. A permanent, non-concentration summon must match this ID to inherit the name. This uses the issue's alternative of matching the subclass companion rather than adding an effect flag: spell wolves remain wolf summons, and temporary summons of even the same monster retain their default name. The generated unit sheet is saved in the battle, preserving names across restarts.

The TV unit card shows the owner's name and companion kind separately. Unit labels and logs continue using the unit sheet's name. Portal naming commands always resolve the requesting member's character. No voiced line is changed or substitutes the dynamic name; no art or sound is generated. Names stay out of explore packets.
