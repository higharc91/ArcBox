# Meridian pixel-art style and asset contract

Status: **refined visual direction approved by the owner on 2026-11-17** in conversation ("Looks good, continue on art assets"). The owner then requested larger, clearer room details for TV. Each follow-on set still gets its own review; no physical-TV readability approval is implied. All samples are original code-built art; generation spend is 0 CU.

## Look and light

Tense, lived-in industrial salvage: chunky hull ribs, inset plating, exposed consoles and restrained warning marks. Avoid glossy reflections, scattered speckle and copied game imagery. Use crisp, connected pixel clusters and selective outlines on crew. Render only at integer multiples with nearest-neighbour filtering; never smooth or fit art fractionally.

All materials use arcpix's six-shade hue-shifted ramps: 0 deep outline, 1 shadow, 2 base-dark, 3 base, 4 light, 5 highlight. Shadows move cool and highlights move warm. No visible pure black or white. Crew outlines use arcpix's selective hue-preserving outline. Player identity colours below are the platform's exact UI exceptions.

Compartment bases are lit **directly overhead**. The four wall bevels share identical shading; equipment gets concentric/centred top lighting. Never bake a north-west cast shadow, directional light spill, text label or crew shadow into a tile: the engine rotates it in 90-degree increments. Crew stays independently oriented.

## File contract

Runtime root: `content/meridian/base/<set>/manifest.json`. Reserved sets: `tiles`, `hatches`, `crew`, `portraits`, `cards`, `icons`, `tokens`, `ui`, `fx`, `audio`. This sample delivers only tiles, hatches and one crew sprite; it does not claim completion of the remaining sets.

Manifests have version/status and entries keyed by rules IDs. Every PNG entry carries a SHA256 and a filename containing its first 12 hex characters. Once referenced/shipped, bytes at that path are immutable: changed pixels create a new hash-named file. The builder retains older files rather than deleting shipped content. Runtime loading must verify manifest hashes and use the declared frame layout; art does not determine legal hatches or movement.

These four IDs (`bridge`, `med_bay`, `reactor_core`, `airlock`) and `ines_okafor` match the actual #329 rules delivered in **unmerged PR #316, head af068bb1**. They are explicit provisional integration keys until those rules land, not newly invented placeholder rules. The manifests record that dependency; no rules or runtime integration are included here.

## Full compartment set (#332)

`python tools/meridian-assets/compartments.py` builds all 48 unique IDs (50 physical tiles) and 57 deck variants, all hatch states, one-way shaft cue, backgrounds, one-shot opening/sealing clips and review evidence. `python tools/meridian-assets/audit_compartments.py --rules <live tiles.json>` fails on any missing ID, deck variant, metadata or hash. The default audit uses checked-out live rules when available, otherwise the explicit pinned reference. The sample-only builder refuses to overwrite a completed full-set manifest.

The set reference is unmerged #316 at `ff3175af859733bf8b02c0ff2afa43d0113e1c66`; `reference/tiles.json` is an exact copy, not an alternate rules pack. Refresh and audit against current upstream rules before integration. Nested `tiles[id].variants[deck]` entries declare each deck's immutable file/hash; runtime chooses the current deck. `hatches.animations[kind][full|reduced]` declares horizontal frames, 10fps, one-shot duration and settled state. Reduced-motion uses the settled state with no animation; reduced-effects sealing omits sparks. These clips prepare assets for M4/M5; they do not claim the full board-FX set (#337).

TV detail pass: main equipment uses broad silhouettes and connected highlights. The 11px card symbols use a warning triangle, handled case and hollow diamond, remaining distinct without hue. Each 1080p readability sheet contains 12 rooms at the actual 128px grid size beside greyscale/crew-occluded versions. Concept deck mocks retain the 128px grid and propose an additional 256px focused-room detail panel. That panel is a review concept, not shipped TV behavior.

## Full crew set (#333)

`python tools/meridian-assets/crew.py` builds all eight content IDs with four facings and living/echo versions of idle (3 frames / 3fps), walk (6 distinct phases / 8fps), hurt (2 / 6fps, one-shot) and down (1 static). Every 24×24 frame uses the same feet anchor (12,22) and a transparent bottom row. Distinct headgear, proportions and projecting role equipment supplement colour; no player ring is painted into a sprite. Echoes preserve the figure's coverage with stable translucent scan bands, without temporal flashing. Reduced motion selects frame 0.

Busts and full-body crew cards are drawn independently of the board sprites, with matching face/headgear/role cues. Names and roles remain live content text. `crew[id].facings[direction][state]` and `crew[id].echo[direction][state]` hold the full strip metadata. Flat `idle` is a true single-frame compatibility image for current M4's whole-image draw; flat `walk` aliases the south walk strip. Those fields prevent the old idle renderer squeezing three poses into one person. Directional animation, echoes and portraits still need the M5 consumer integration.

`python tools/meridian-assets/audit_crew.py --rules <current crew.json>` enforces exact content/state coverage, names/roles, frame layouts, immutable hashes and the static-idle compatibility contract. A source-only style build refuses to overwrite either completed tiles or crew; use `build.py --root <separate temporary root>` for historical sample regeneration. Full builders can run in order: `compartments.py`, then `crew.py`.

## Card frames and item icons (#334)

`python tools/meridian-assets/cards.py` builds three 64×64 nine-slice frames, matching 16×16 / 24×24 kind glyphs and all twenty 24×24 first-wave item icons. Twelve source pixels per edge are declared as `insets`; `contentInset` is 16 source pixels. Border corners render at whole nearest multiples; stretch bands and centres are uniform so they add no distorted micro-detail. All titles, kind names, flavour and mechanics remain live text. Frames differ through warning triangles, square case brackets/rivets and hollow diamond corners as well as palette. Icons are individual broad object compositions, with no animated detail competing with reading.

`cards/manifest.json` maps every card ID to kind/frame and optional item icon; `icons/manifest.json` maps item IDs and both symbol sizes. The reference is #316 at `00d4a52bb9c7e73a5ee72b117b91891e6c0cdd11`. The strict coverage audit rejects missing items and new M7 items without an authored recipe. Review all 32 real cards at phone and TV sizes in `docs/superpowers/reports/meridian-art/cards/index.html`. TV body/title fonts are 30px/38px; a long choice uses a wider panel at the same font size. Phone uses 18px/25px. Whole 2×/3× icons supplement live names and kind labels. This set prepares M5 integration; it does not install a game renderer or controller flow.
