# Meridian pixel-art style and asset contract

Status: **proposal awaiting owner approval for #331**. Do not start #332–#338's full sets before that approval. All samples are original code-built art; generation spend is 0 CU.

## Look and light

Tense, lived-in industrial salvage: chunky hull ribs, inset plating, exposed consoles and restrained warning marks. Avoid glossy reflections, scattered speckle and copied game imagery. Use crisp, connected pixel clusters and selective outlines on crew. Render only at integer multiples with nearest-neighbour filtering; never smooth or fit art fractionally.

All materials use arcpix's six-shade hue-shifted ramps: 0 deep outline, 1 shadow, 2 base-dark, 3 base, 4 light, 5 highlight. Shadows move cool and highlights move warm. No visible pure black or white. Crew outlines use arcpix's selective hue-preserving outline. Player identity colours below are the platform's exact UI exceptions.

Compartment bases are lit **directly overhead**. The four wall bevels share identical shading; equipment gets concentric/centred top lighting. Never bake a north-west cast shadow, directional light spill, text label or crew shadow into a tile: the engine rotates it in 90-degree increments. Crew stays independently oriented.

## File contract

Runtime root: `content/meridian/base/<set>/manifest.json`. Reserved sets: `tiles`, `hatches`, `crew`, `portraits`, `cards`, `icons`, `tokens`, `ui`, `fx`, `audio`. This sample delivers only tiles, hatches and one crew sprite; it does not claim completion of the remaining sets.

Manifests have version/status and entries keyed by rules IDs. Every PNG entry carries a SHA256 and a filename containing its first 12 hex characters. Once referenced/shipped, bytes at that path are immutable: changed pixels create a new hash-named file. The builder retains older files rather than deleting shipped content. Runtime loading must verify manifest hashes and use the declared frame layout; art does not determine legal hatches or movement.

These four IDs (`bridge`, `med_bay`, `reactor_core`, `airlock`) and `ines_okafor` match the actual #329 rules delivered in **unmerged PR #316, head af068bb1**. They are explicit provisional integration keys until those rules land, not newly invented placeholder rules. The manifests record that dependency; no rules or runtime integration are included here.

Sources: `tools/meridian-assets/build.py`, using `arcpix.canvas.Canvas` slot/shade pixels and `arcpix.palette.ramp`. Dependencies are the existing Pillow/numpy toolchain. Run `python3 tools/meridian-assets/build.py`, then `python3 -m unittest discover -s tools/meridian-assets -p 'test_*.py'`. A second build must be byte-identical. Tests check edge rotation/light, frame bounds, hatch shapes, palette and manifest hashes.

## Review and approval

Review: `docs/superpowers/reports/meridian-art/style/index.html`. It shows every room/hatch pairing at 1× and 2×, standing/walking beside a tile, and a 1920×1080 partly explored deck mock with two crew. Repeated sample rooms demonstrate spacing, not a legal tile draw or an implemented game. The walk animation respects reduced motion and has a pause control. Small screens scroll the native-size mock inside its own labelled panel, rather than scaling pixels fractionally.

Review real Chromium at 320×844 and 390×844 and a native Godot display of the mock. Retain actual protanopia/deuteranopia simulations; they are limited screenshot checks, not human couch/stream readability approval. Ask the owner to judge the look and readability before full production. No human or physical-TV test is implied.

Paid generation requires an issue-posted estimate and explicit owner approval first, as #331 specifies. None is used in this delivery.
